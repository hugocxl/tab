Install Tab and find your way around

  • Version {{version}}
  • {{date-long}}

Tab is a native Mac app with a terminal multiplexer, agent panes, simulators and a browser in one workspace. These pages cover installing it, what each pane needs, how its server keeps your work running and how to build it yourself.

Install

  1. Download the latest disk image from GitHub.
  2. Drag Tab into Applications.
  3. Open Tab and open a project folder.

Tab keeps itself up to date. New versions download in the background and install when Tab quits, or while you’re away or Tab is hidden, coming back just as it was. The server moves to the new version while nothing is working, and every terminal reopens where it was, with its output. Restart installs right away, asking first only if a running program would stop. Check for Updates looks right away, and Settings › General › Updates turns each step off.

Requirements

Tab runs on Apple silicon Macs with macOS 14 or later. Some panes rely on tools you install yourself.

ForYou need
TabA Mac with Apple silicon and macOS 14 or later
Agent panesClaude Code or Codex, installed and signed in on the Mac running your workspace
iOS simulatorsXcode and a simulator runtime
Android emulatorsThe Android SDK and an emulator
A remote MacTab installed there, reachable over SSH

Tab is free and open source. It doesn’t include an agent subscription: you use your own provider account, and its fees are separate.

Tabs and panes

A tab is one card in the sidebar, and it holds a split layout of panes. A project or Git worktree is a single tab, and Home holds one tab per card.

A pane is one terminal, agent, browser, simulator, editor or diff inside a tab. New Tab always adds a card, and New Pane adds a pane beside the one you’re in.

Terminals that keep running

Tab’s background server, tabd, owns your terminals, agent conversations, projects, tabs and history. The app and the tab command start it when it isn’t running. Quit the app and your terminals keep going; open it again and it reconnects.

The Mac running your workspace needs to stay awake. Closing a terminal pane ends that terminal.

Restarting the server keeps your layout. Each terminal reopens in its pane and folder with its output above a new shell, and agents that were working pick up where they left off. tab server restart waits until no program or agent is working; --force stops them.

Remote Macs

Connect to another Mac over SSH and its projects, terminals and simulators open in your app. Processes, files and network belong to that Mac. Browser panes load its pages through the server’s tunnels, so localhost is the remote Mac’s, and its simulators stream to you as video.

The tab command

The app bundle includes the tab command line tool. Run Install Command Line Tool from the command palette to link it at ~/.local/bin/tab.

tab --help
CommandWhat it does
tab sessionTerminals that keep running, with or without the app
tab agentRead, wait for and message Tab’s agent conversations
tab projectThe folders Tab works in
tab worktreeGit worktrees, each a project of its own
tab simulatorThe server’s iOS simulators and Android emulators
tab forwardReach a server’s port from this computer
tab paneAdd, list, focus, close, move and resize panes in the app
tab browserDrive a browser pane: read, click, type and wait

Add --host to work with another Mac’s server over SSH. tab help followed by a command explains it in full.

Branch settings

Every checkout Tab opens is a branch: a project’s own folder is its default branch, and each worktree is another branch. A settings.json says where worktrees go and what runs when a branch opens or closes in Tab, without asking.

{
  "defaultBranch": {
    "name": "main",
    "open": ["npm ci"],
    "close": [{ "name": "Stop services", "command": "docker compose down" }]
  },
  "worktrees": {
    "location": "../{base-dir}.{branch}",
    "open": ["npm ci", "cp \"$TAB_PROJECT_PATH/.env\" ."],
    "close": ["docker compose down"]
  }
}

Put it in ~/.config/tab/settings.json for every project, or commit it as .config/tab/settings.json in a project. The project’s name and location win; commands add up, yours first on open and the project’s first on close. Every key is optional.

The default branch’s open runs when the project is added and close when it is removed. A worktree’s run after it is created and before it is removed. Commands run in the branch’s folder with TAB_PROJECT_PATH, TAB_BRANCH and TAB_BRANCH_PATH, plus TAB_WORKTREE_ID and TAB_WORKTREE_NAME for worktrees.

Teach your agents to use Tab

One command installs the tab-cli skill into Claude Code, Codex, OpenCode and Pi, and hooks into Claude Code and Codex. Agents then know how to open panes, read terminals and drive the browser, and Tab sees whether each one is working, blocked or idle.

tab integrations install

tab integrations remove takes them out again. Codex runs a new hook only after you approve it with /hooks.

Build from source

You’ll need Xcode’s Swift 6 toolchain and Zig 0.17 to build the vendored terminal framework. Build GhosttyVT once, then validate the app.

scripts/build-ghostty.sh
scripts/validate.sh

Validation builds with warnings as errors, runs the tests and creates build/debug/Tab Dev.app. For faster iteration use swift build, and to bundle and launch the development app with this checkout’s profile:

scripts/run-dev.sh

AGENTS.md describes the architecture and the contribution rules.
